\title{ProvBench-RAG: A Benchmark Resource for Provenance-Sensitive Retrieval Under Near-Duplicate Source Confusion}

\begin{document}

\begin{abstract}
Retrieval-augmented systems are often evaluated on whether \emph{some} passage supports an answer, but deployed pipelines must also choose the correct \emph{document instance} among near-duplicates (mirrors, stale snapshots, scraped copies, jurisdiction variants).
We release \textbf{ProvBench-RAG}, an open benchmark resource comprising JSONL schemas, three reproducible tracks (\ProvBenchNumQueries{} synthetic clusters, \WikiNumQueries{} Wikipedia revision clusters, \CombinedNumQueries{} pooled queries), deterministic evaluation code, and reference baseline rankings.
The resource exposes \textbf{preferred-source accuracy} (PSA@1) and composite \textbf{ProvScore} alongside standard recall/nDCG.
On the synthetic track, lexical BM25 achieves PSA@1 $=0$ under planted decoys while a bundled provenance reranker (PACER) reaches \ProvPacerPSA{}; Wikipedia and pooled tracks quantify transfer and heterogeneous-index stress.
All data, metrics, and paper tables regenerate from the public repository (see Section~\ref{sec:avail}).
\end{abstract}

\section{Introduction}
Near-duplicate \emph{source confusion} arises when many passages match a query lexically yet differ in authority, validity interval, copy type, or jurisdiction.
Existing RAG benchmarks~\cite{lewis2020retrieval,jacovi2025facts,krishna2024frames,huwiler2025versionrag} rarely annotate which competing instance should be cited when metadata diverges.

\textbf{Resource contribution.} ProvBench-RAG is a \emph{benchmark package}, not a new neural ranker: (i)~clustered JSONL corpora with gold preferred sources $P^\ast$, evidence/minimal sets, and conflict abstention; (ii)~a Python toolkit for indexing, metrics, and significance tests; (iii)~reference rankings (BM25, heuristics, PACER) to sanity-check the task.
Researchers can plug in dense retrievers or cross-encoders while holding annotations fixed.

\section{Resource design}
\subsection{Schema}
Each \texttt{document} record carries \texttt{cluster\_id}, provenance fields (\texttt{authority\_level}, validity dates, \texttt{original\_or\_copy\_label}, \texttt{jurisdiction}), and text.
Each \texttt{query} record carries \texttt{gold\_answer}, \texttt{gold\_evidence\_ids}, \texttt{minimal\_evidence\_ids}, \texttt{preferred\_source\_ids}, optional \texttt{query\_time}/\texttt{query\_jurisdiction}, and \texttt{abstain\_required}.
Clusters record \texttt{relation\_type} (e.g., \texttt{original\_vs\_copy}, \texttt{fresh\_vs\_stale}).

\subsection{Tracks}
Table~\ref{tab:tracks} lists released splits.
The \textbf{synthetic} generator (seed 42) plants five families of 300 clusters with lexical decoys in families B--D.
The \textbf{Wikipedia} track fetches three revisions per article via the public MediaWiki API~\cite{wiki_api} with programmatic gold on the newest revision.
The \textbf{combined} track concatenates synthetic and Wikipedia JSONL into one BM25 index to simulate heterogeneous corpora without routing.

\subsection{Metrics}
Submissions report ranked lists $R(q)$.
We distribute implementations for recall@$k$, nDCG@$k$, PSA@1 (top rank $\in P^\ast$), provenance F1@3, and composite ProvScore ($0.25$ Ans + $0.25$ PSA + $0.20$ Suff + $0.15$ Min + $0.15$ Abst).

\textbf{Utility.} The synthetic track separates high recall from PSA@1 failure under decoys---a pattern standard QA retrieval scores under-report.
Wikipedia provides a noisy real revision stress test (low absolute PSA).
Combined quantifies lexical collapse when query conventions mix.

\section{Ethics and limitations}
Synthetic clusters are templated; Wikipedia gold is programmatic (first sentence of newest revision).
Conflict queries use rule-based abstention, not crowd adjudication.
The resource is English-only and BM25-centric at release; extensions welcome via the same JSONL schema.
