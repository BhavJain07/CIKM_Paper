\title{ProvBench-RAG: A Benchmark Resource for Provenance-Sensitive Retrieval Under Near-Duplicate Source Confusion}

\begin{document}

\begin{abstract}
Retrieval-augmented systems are often evaluated on whether \emph{some} passage supports an answer, but deployed pipelines must also choose the correct \emph{document instance} among near-duplicates (mirrors, stale snapshots, scraped copies, jurisdiction variants).
We release \textbf{ProvBench-RAG}, an open benchmark resource comprising JSONL schemas, three reproducible tracks (\ProvBenchNumQueries{} synthetic clusters, \WikiNumQueries{} Wikipedia revision clusters, \CombinedNumQueries{} pooled queries), deterministic evaluation code, and reference baseline rankings.
The resource exposes \textbf{preferred-source accuracy} (PSA@1) and composite \textbf{ProvScore} alongside standard recall/nDCG.
On the synthetic track, lexical BM25 achieves PSA@1 $=0$ under planted decoys while a bundled provenance reranker (PACER) reaches \ProvPacerPSA{}; Wikipedia and pooled tracks quantify transfer and heterogeneous-index stress.
All data, metrics, and paper tables regenerate from the public repository (Section~\ref{sec:avail}).
\end{abstract}

\section{Introduction}
Near-duplicate \emph{source confusion} arises when many passages match a query lexically yet differ in authority, validity interval, copy type, or jurisdiction.
Existing RAG benchmarks~\cite{lewis2020retrieval,jacovi2025facts,krishna2024frames,huwiler2025versionrag,thakur2021beir} and automated RAG evaluators~\cite{es2023ragas,gao2024rag_survey} rarely annotate which competing instance should be cited when metadata diverges; provenance-aware retrieval remains under-specified in standard IR toolchains~\cite{saad2022provenance,robertson2009bm25,lin2021pyserini}.

\textbf{Resource contribution.} ProvBench-RAG is a \emph{benchmark package}, not a new neural ranker: (i)~clustered JSONL corpora with gold preferred sources $P^\ast$, evidence/minimal sets, and conflict abstention; (ii)~a Python toolkit for indexing, metrics, and significance tests; (iii)~reference rankings (BM25, heuristics, PACER) to sanity-check the task.
Researchers can plug in dense retrievers or cross-encoders while holding annotations fixed.

\section{Resource design}
\subsection{Schema}
Data fields are organized around nested source attributes to reduce parsing errors under high lexical overlap:
\begin{itemize}
    \item \textbf{Document records:} \texttt{cluster\_id}, \texttt{text}, and provenance keys (\texttt{authority\_level}, validity dates, \texttt{original\_or\_copy\_label}, \texttt{jurisdiction}).
    \item \textbf{Query records:} \texttt{gold\_answer}, \texttt{gold\_evidence\_ids}, \texttt{minimal\_evidence\_ids}, \texttt{preferred\_source\_ids}, plus \texttt{query\_time}, \texttt{query\_jurisdiction}, and \texttt{abstain\_required}.
    \item \textbf{Cluster groupings:} a global \texttt{relation\_type} per cluster (e.g., \texttt{original\_vs\_copy}, \texttt{fresh\_vs\_stale}).
\end{itemize}

\subsection{Tracks}
Table~\ref{tab:tracks} lists released splits (query counts are \emph{total} per track).
The \textbf{synthetic} generator (seed 42) plants five families of 300 clusters with lexical decoys in families B--D.
The \textbf{Wikipedia} track fetches three revisions per article via the public MediaWiki API~\cite{wiki_api} with programmatic gold on the newest revision.
The \textbf{combined} track concatenates synthetic and Wikipedia JSONL into one BM25 index to simulate heterogeneous corpora without routing.

\subsection{Metrics}
Submissions report ranked lists $R(q)$.
We distribute implementations for recall@$k$, nDCG@$k$, PSA@1 (top rank $\in P^\ast$ on \emph{non-abstain} queries), provenance F1@3, and composite ProvScore ($0.25$ Ans + $0.25$ PSA + $0.20$ Suff + $0.15$ Min + $0.15$ Abst).
Conflict-track queries require abstention; PSA@1 and paired McNemar tests therefore use the non-abstain subset (1,200 of 1,500 synthetic; 1,340 of 1,640 combined; all 140 Wikipedia queries).

\section{Availability and reproduction}
\label{sec:avail}
\textbf{Code and data.} GitHub: \url{https://github.com/BhavJain07/CIKM_Paper}.
The repository includes \texttt{provbench\_rag/} (schemas, BM25 index, metrics), frozen JSONL under \texttt{corpora/annotations/}, and \texttt{results/*/metrics.json}.
One-command reproduction: \texttt{bash scripts/reproduce\_full.sh} rebuilds corpora (optional Wikipedia crawl), reruns evaluations, and exports LaTeX table fragments.

\textbf{Archive.} A Zenodo deposit is \emph{reserved} (DOI to be minted at camera-ready; see \texttt{ZENODO.md}); annotation bundles will be archived for long-term citation alongside GitHub tags.

\textbf{Sustainability.} v1 artifacts are frozen under git tags; issue templates accept community pull requests for new tracks (e.g., dense retriever pools) reviewed by the maintainer.
Hosting is static (GitHub + Zenodo); no paid API keys are required beyond optional Wikipedia re-crawls.
The maintainer commits to answering breakage reports for two years post-release and documenting schema migrations in \texttt{CHANGELOG.md}.

\textbf{Licensing.} Code: MIT. Synthetic text: generated without PII. Wikipedia passages: CC BY-SA 4.0 via the Wikimedia API~\cite{wiki_api}, with conservative request delays and revision IDs stored in JSONL.

Dataset card: \texttt{corpora/DATASET.md} documents provenance, licenses, and FAIR attributes.

\textbf{Utility.} The synthetic track separates high recall from PSA@1 failure under decoys---a pattern standard QA retrieval scores under-report.
Wikipedia provides a noisy real revision stress test (low absolute PSA).
Combined quantifies lexical collapse when query conventions mix.

\section{Ethics and limitations}
Synthetic clusters are templated; Wikipedia gold is programmatic (first sentence of newest revision).
Conflict queries use rule-based abstention, not crowd adjudication.
The resource is English-only and BM25-centric at release; extensions welcome via the same JSONL schema.
